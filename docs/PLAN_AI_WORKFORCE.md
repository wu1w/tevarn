# Takton 北极星计划 · AI Workforce（数字员工）

> 版本：v1 · 日期：2026-07-27 · 状态：战略共识已定稿，待评审
>
> 本文是 Takton 的产品北极星文档。它不描述下一个 sprint 做什么，
> 而描述 Takton **最终要成为什么**、以及为什么 v0.4 Agent Kernel 的
> 每一项基础设施都是朝这个方向的前置投资。
>
> 一句话定位：**"Takton is not where you run tasks. Takton is where your AI workforce lives."**

---

## 1. 愿景与定位

### 1.1 从「Build Better Agents」到「Build Persistent Digital Workers」

过去两年所有 Agent 产品（Claude Code / Codex / Hermes / Manus）都在同一个维度
竞争：**把单个 task 完成得更好**——更多工具、更强 skill、更复杂的 workflow。
这条路的问题是：

- task 是**无状态的消耗品**。干完即焚，经验不沉淀，第 100 次干的 Agent
  和第 1 次干的 Agent 是同一个新手。
- 在 task 维度竞争本质是在**模型能力**维度竞争——模型一换代，工具层
  的护城河全部归零。

Takton 的战略转向：**Agent 成为第一公民，Task 只是 Agent 生命周期中的事件**。
用户不再「跑一次任务」，而是「雇佣一名数字员工」——它有名字、有职责、
有记忆、有工作记录，在用户不在场的时候持续运转并变得更好。

### 1.2 检验标准：三个月测试

衡量这个愿景是否成立的唯一问题：

> **如果用户三个月不打开 Takton，Takton 自己还能创造什么价值？**

这是 AI 从**同步软件**变为**异步软件**的分水岭。同步软件的承诺是
「我帮你干活」（你发起、你等待、你验收）；异步软件的承诺是
「**当你回来时，工作已经推进了**」。后者的产品形态不是更好的对话框，
而是一个有编制、有考勤、有成长的数字团队。

---

## 2. 核心抽象转变：Task → Agent

| 维度 | 旧抽象（Task 中心） | 新抽象（Agent 中心） |
|---|---|---|
| 第一公民 | Task / Workflow | Agent（持久软件对象） |
| 状态 | task.result（一次性） | Agent 的事件流 + 四层记忆 |
| 上下文 | 会话级，断线即失 | 身份级，休眠-唤醒后续作 |
| 能力 | 堆 skill / 工具 | Agent 本身在成长（方法论沉淀） |
| 用户关系 | 发起-等待-验收 | 雇佣-授权-查收汇报 |
| 成本模型 | 每 task 计费 | 编制内预算（本地模型边际成本≈0） |

工程含义：v0.4 已有的 `AgentProcess` 是**运行时对象**，0.5 起要变成
**持久对象**——进程可以死，Agent 不死。这是后续所有设计的地基。

## 3. 六大支柱

按优先级 / 依赖顺序排列。e 依赖 a–d，f 依赖 a–c。

### 3.a Identity System（身份系统）

**目标**：每个 Agent 是一个持续存在的软件对象，拥有持久 ID、长期记忆、
权限边界、工作记录、信用与技能成长史。用户拥有的是一支数字团队，
不是一堆 workflow。

**设计要点**：
- `AgentIdentity`：全局唯一 ID + 名称 + 职责描述 + 创建者 + 创建时间，
  独立于任何运行时进程存在。
- 权限即身份的一部分：Agent 的能力边界（CapabilityToken 收窄结果）
  随身份持久化，重启后不变、不可自行扩大。
- 工作记录与信用：每次执行的成功/失败/预算消耗归入该身份的档案，
  构成「绩效」，供进化与组织层消费。
- 技能成长史：skill 的获得/淘汰/改造挂到身份时间线上，可追溯
  「它是怎么变成今天这样的」。

**工程红线**：
- 身份与进程严格分离：`AgentProcess` 可销毁，`AgentIdentity` 不可销毁
  （只能停用/归档，审计链不可断）。
- 身份的权限变更必须产生审计事件，禁止静默改权。

**与现有 Kernel 的衔接点**：
- 工牌 = `AgentProcess` + parent 链 → 需把 parent 链与生命周期事件
  **持久化**（当前只在内存）。
- 劳动合同 = Intent 合成 + CapabilityToken（HMAC 签名）→ 已具备，
  需把 token 的签发/收窄记录挂到身份档案。
- 考勤 = 哈希链审计 → 已落盘，直接复用为身份的工作记录骨架。

### 3.b Event Sourcing（唯一事实来源）

**目标**：不存「当前状态」，存「经历了哪些事件」。任何状态都是事件流
的推导结果；事件流是唯一事实来源。

**设计要点**：
- 事件类型覆盖：生命周期（spawn/suspend/resume/terminate）、
  执行（intent/mediate/tool_call/budget）、权限变更、记忆写入、
  进化建议与审批、收件箱收发。
- 事件追加进现有哈希链审计流，天然防篡改——审计链从「合规副产品」
  升级为「状态重建机制」。
- 状态 = fold(events from last checkpoint) + checkpoint。

**工程红线**：
- **必须 快照（checkpoint）+ 增量事件，禁止全量 replay**。
  老员工的事件流 replay 成本随工龄线性增长，没有快照机制的
  Event Sourcing 是在给三个月后的自己埋雷。
- 快照本身是派生数据，可丢弃重建；事件不可丢弃。
- 快照频率策略（按事件数/按时间）必须可调，默认值写入配置而非硬编码。

**与现有 Kernel 的衔接点**：
- 哈希链审计落盘已实现 → 直接升级为事件存储（event store），
  补事件类型 schema 与 checkpoint 表。

### 3.c Memory 四层

**目标**：记忆不是一个大向量库，而是四层各司其职的结构。

| 层 | 内容 | 生命周期 | 现有基础 |
|---|---|---|---|
| Working | 当前执行上下文 | 单次执行 | 已有会话上下文 |
| Episodic | 工作经历：做过什么、结果如何 | 长期，可压缩归档 | 事件流（3.b）天然提供 |
| Semantic | 从经历中抽象出的知识/事实 | 长期 | 知识库基础设施可复用 |
| **Identity Memory** | 人格、职责、经验、偏好、方法论 | 与身份同寿 | **行业空白，本文重点** |

**设计要点**：
- Identity Memory 是 Takton 的差异化核心：Letta/MemGPT 做了
  persistent + memory，但记忆是「关于世界的」，没有「关于自己是谁、
  怎么干活更好」这一层。
- 写入路径分离：Episodic 自动写（事件流副产品）；Semantic 与
  Identity Memory 由**提炼流程**写入（定期从 Episodic 蒸馏），
  蒸馏结果走进化审批（3.d）。
- 读取按层预算：Working 进上下文窗口；Identity Memory 常驻
  system 侧；Episodic/Semantic 检索式取用。

**工程红线**：
- 四层各有独立的存储与淘汰策略，禁止混在一个表/一个索引里。
- Identity Memory 的任何修改必须可追溯到一次审批事件。

**与现有 Kernel 的衔接点**：
- 现有哈希链审计 = Episodic 层的原料；`mediate` 执行中介是
  记忆读取的天然挂载点。

### 3.d Agent Evolution（受控进化）

**目标**：成长的是 Agent 本身，不是它的工具箱。Skill 只是能力；
进化是方法论沉淀、Planner 自调、低效工具淘汰、知识结构形成。

**设计要点**：
- 进化输入：Episodic 记忆（工作记录）+ 绩效统计（成功率/预算效率）。
- 进化产出形式：**述职报告式的建议**——「我注意到 X 类任务我用
  工具 A 的失败率是 B 的 3 倍，建议调整 planner 偏好 / 弃用 A /
  沉淀 SOP 如下」。
- 审批通过后才落为 Identity Memory / planner 配置变更。

**工程红线**：
- **`auto_apply=False` 不可绕过**。进化产出永远是「建议」，
  人工确认才生效——员工可以写述职报告，升职决定权在老板手里。
  任何配置项、环境变量、内部 API 都不得提供自动应用进化的后门。
- 每次进化（建议、审批、应用、回滚）全程进事件流。

**与现有 Kernel 的衔接点**：
- v0.4 已有 evolution 建议模块（`auto_apply=False`）与 bwrap 沙箱
  skill 自动生成（培训）→ 0.7 将其从「skill 级」提升到「Agent 级」。

### 3.e Agent Organization（最后做，预期涌现）

**目标**：不是 Multi-Agent 调用编排，而是**组织结构**——
Manager / Research / Coding / Finance 各有职责、权限、预算、目标，
Organization 持有长期 Objective。

**设计判断**：
- 有了 a–d（身份、事件、记忆、进化）之后，汇报线会**自然涌现**：
  谁给谁派活、谁审批谁的预算，都是身份间的关系数据。
- 提前自顶向下设计组织 schema 是过度工程——0.7 之前只做观察，
  从真实使用里归纳结构，再固化。

**工程红线**：
- 0.5/0.6 阶段**不实现**任何组织层代码，只在事件 schema 里预留
  `delegated_by` / `reports_to` 字段。
- 组织预算 = 各 Agent 预算的层级聚合，复用现有 token 预算机制，
  不新造一套。

### 3.f 异步运转引擎

**目标**：让 workforce 在用户不在场时运转。

**设计要点**：
- **Agent 收件箱**：cron / webhook / 邮件 / 文件变更统一转工单，
  进入 Agent 的 inbox。现有 cron 从「定时触发脚本」升级为
  「定时给员工派活」。
- **休眠-唤醒-续作**：Agent 无事可做时休眠（状态已由事件流+快照
  持久化），有工单时唤醒，从 Identity Memory + Episodic 恢复上下文
  继续干活。
- **日报**：「你不在的这段时间」——首页不再是空白对话框，
  而是 workforce 的工作汇报。

**工程红线**：
- 唤醒路径必须经过 mediate 执行中介，异步入口不得绕过权限与预算。
- 收件箱积压要有界（队列上限 + 溢出策略），禁止无界堆积。

**与现有 Kernel 的衔接点**：
- 排班 = cron → 改造为收件箱触发器。
- 薪酬 = token 预算 → 已有，异步执行同样走预算扣减。

## 5. 差异化与竞争格局

- **Letta (MemGPT)**：做了 persistent agent + memory，验证方向正确；
  但**无控制面**——没有能力收窄、没有预算、没有审计、没有审批进化。
  Takton = persistent + memory + **控制面（Kernel）**。
- **Ping Identity 2026.3 发布 Identity for AI**：企业级厂商下场验证
  「Agent 身份」是真实需求。身份层将成为 Agent 时代最重要的一层——
  安全威胁从「偷数据」变为「**劫持代理权**」，谁代表你行动、
  能被授予多大权限，是新的攻击面。
- **成本结构**：云端 persistent agent 7×24 运转按 token 烧钱，
  「一直在线」在商业上不成立；Takton 本地模型（5080 / MI210）
  边际成本为零，**私有部署从隐私卖点变为商业模式优势**——
  只有本地算力养得起一支永不下班的团队。

## 6. 版本路线图

### 0.5 编制与档案
**范围**：Identity System（持久身份 + 档案）+ AgentProcess 持久化 +
Event Sourcing（事件 schema + checkpoint 快照）+ Memory 四层骨架。
**验收**：
- 杀掉进程、重启服务后，Agent 身份/权限/记忆/工作记录完整恢复；
- 恢复路径走 checkpoint + 增量事件，测试断言**不触发全量 replay**；
- 权限收窄结果在重启后不变，且任何变更可在事件流中追溯。

### 0.6 自主运转
**范围**：Agent 收件箱（cron/webhook/邮件/文件变更 → 工单）+
休眠-唤醒-续作 + 日报。
**验收**（iPhone 时刻的具体形态）：
- 用户离开一段时间后回来，打开 Takton 首页看到的是
  **workforce 工作汇报**，而不是空白对话框；
- 休眠 Agent 被工单唤醒后，能基于 Identity/Episodic 记忆
  续作此前的任务，无需用户重述上下文；
- 异步执行全程过 mediate，预算扣减与审计链完整。

### 0.7 成长与组织
**范围**：Agent 级受控进化（方法论沉淀 / planner 自调 / 工具淘汰，
全部走人工审批）+ 汇报线涌现观察 + 组织预算聚合。
**验收**：
- 进化建议 → 审批 → 应用 → 回滚全链路有事件记录；
- 不存在任何绕过人工审批的自动应用路径（含配置项与环境变量）；
- 从真实使用中归纳出至少一条自然涌现的汇报关系并固化。

## 7. 工程红线（全版本通用）

1. **写保护仅限 `/opt/hermes-workspace/`**：任何 Agent（含异步唤醒的）
   写操作不得越出该目录；沙箱不可用时报错而非降级。
2. **零 mock 测试**：测试必须打真实实现/真实存储，没有依赖就拒绝运行，
   不产出看似成功的假数据。
3. **进化人工审批不可绕过**：`auto_apply=False` 是硬约束，
   不存在配置/环境变量/内部 API 形式的后门。
4. **事件快照机制**：状态恢复必须 checkpoint + 增量事件，
   禁止全量 replay；快照策略可调。
5. **asyncio 单线程假设**：kernel 各模块建立在事件循环单线程假设上，
   任何 kernel 方法在引入 `await` 之前必须先加锁，防止跨 await 的
   状态撕裂（预算、审计链、事件追加顺序均依赖此假设）。

## 8. 风险与约束

| 风险 | 说明 | 缓解 |
|---|---|---|
| 记忆膨胀 | 90 天 × N Agent 的 Episodic 持续增长 | 快照 + 蒸馏归档 + 分层淘汰策略；容量指标进日报 |
| 异步失控 | 用户不在场时 Agent 自主行动的风险面扩大 | 所有异步路径过 mediate；CapabilityToken 收窄；预算硬顶；审计链全程 |
| 进化漂移 | 蒸馏/进化把错误经验固化进 Identity Memory | 人工审批 + 可回滚 + 进化前后绩效对比进事件流 |
| 组织层过度工程 | 提前设计组织 schema 浪费且大概率错 | 0.7 前只观察不实现（见 3.e） |
| 本地模型能力上限 | 5080/MI210 能跑的模型弱于云端旗舰 | 用记忆与分工补单体智能；质量验收看「代际进步」而非绝对水平 |
| 身份即攻击面 | 劫持代理权成为新威胁 | 身份层权限变更全程审计；HMAC 签名；私钥不出本机 |

## 9. 验收标准：三个月测试场景

**场景**：创建一个 Research Agent，配置每日定时收件箱任务
（如「每日调研 X 领域动态并归档」），然后**三个月不打开 Takton**。

第 90 天回来时检查：

1. **身份与记忆**：Identity Memory 中是否沉淀了可读的
   方法论/SOP（非原始日志堆砌）；Episodic 记录完整可回溯到第 1 天。
2. **代际进步（可测量）**：用同一组机器可验证的评测任务
   （复用 `scripts/bench_agent/` 思路，不用 LLM 当裁判）分别测
   第 1 天快照与第 90 天状态的产出质量，**第 90 天必须高于第 1 天**。
3. **成本与稳定**：90 天事件流下恢复时间有界（checkpoint 生效，
   非全量 replay）；本地算力总成本 ≈ 电费；审计链 90 天无断链。
4. **汇报体验**：首页日报能回答「你不在的这 90 天发生了什么」，
   无需翻原始日志。

这条标准通过，北极星即成立；不通过，说明六大支柱中至少一根是伪需求，
按事件流数据定位是哪根，再迭代。
