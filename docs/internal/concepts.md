# Alpha 用户概念表（0.4.6+）

对外只保留用户能记住的 **3 个词**。其余能力映射到这三者之下，或标为「高级」。

| 用户说法 | 系统实体 | 说明 |
|----------|----------|------|
| **员工** | `AgentIdentity` | 持久编制档案：姓名、职责、权限、预算、记忆。进程可死，员工不死。 |
| **工单** | `AgentInboxItem`（+ 关联 process/run） | 派给某员工的一条活：pending → claimed → done/failed/cancelled。 |
| **审批** | Escalation + Evolution proposal | 越权提权、进化提案等人审入口；默认不静默改权。 |

机器可读同源：`GET /api/kernel/protocol/concepts`（`backend/kernel/protocol_spec.py`）。

## 映射（内部，不对用户讲新名词）

| 旧/工程名 | 对用户怎么说 |
|-----------|----------------|
| SubAgent / 岗位模板 | **员工技能包 / 模板**（招人时自动生成并挂到员工；不是可派活的「员工」） |
| Kernel Process | 员工**正在执行**的一次任务运行 |
| Cluster / Workflow / Goal | **高级**；侧栏不占主位，URL 仍可直达 |
| Hire Wizard | **新建员工** |
| Workforce report | **日报 / 工作汇报** |

## 主路径（产品脊柱）

**默认入口是对话，不是页面点击。**

```
用户 ──对话──► CEO（大管家 / 如「小白」）
                 │  系统自动注入「大管家编排纪律」+ crew 工具面
                 ├─ 分析需求、拆子任务
                 ├─ crew_steward.hire   → 员工 Identity（缺人时）
                 ├─ crew_steward.assign → 工单 Inbox（派给合适员工）
                 ├─ list / status       → 掌控班子
                 └─ 危险操作 → 弹窗：一次 / 本会话 / 本员工
员工 ──Dispatcher──► 按权限/预算执行工单 → credit / 日报可查
```

**不是**：CEO 起一堆 SubAgent 迷你 Run 闷头干（无工单、无 credit、不进员工列表）。

`delegate_task` / `agent_call` 在有编制时同样改走 **Inbox assign**，禁止无编制时的临时子代理闷跑。

页面（员工列表、权限看板、审批）用于**观察与纠偏**，不作为日常操作主路径。

成功判据：只和 CEO 说话即可搭班子、派活；派完后员工收件箱有工单；危险操作可按会话/员工记住授权。

## 权限分层（别把安全点成刷屏）

| 谁在干活 | 工具调用谁批 | 主人要不要点 |
|----------|--------------|--------------|
| **员工（工单）** | **CEO 编制策略**（Identity.capabilities + 映射） | **否**。不弹「允许一次」洪水 |
| **主人 ↔ CEO 对话** | 危险操作可弹窗（一次/会话/本员工） | 可 |
| **策略/节点** | 主人 | **是**（clarify / 目标方向 / 里程碑） |

员工越权工具 → 拒 + 提示在权限看板扩权，**不**刷审批台。  
安全通知太多 = 没有安全；真正要人决策的是方向，不是每一次 `glob`。
